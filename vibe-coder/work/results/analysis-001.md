# Results: Analyse the customer requirements, design and plan the steps

> AI-managed only — humans do not edit this file.

## Summary

Still Cup is a well-scoped WordPress + WooCommerce launch: six variable products, AU shipping/payments, editable content, and a calm premium theme aligned to the Pencil artboards. Build as a minimal child theme with native WooCommerce (Stripe + PayPal), staged catalogue/test data, then owner-supplied assets and acceptance against R01–R15.

## Findings

### 1. Requirements shape

- **Platform (R01, R13):** WordPress + WooCommerce with block/templates and Shop Manager + customer-owned Admin. Routine work must not depend on PHP or a hard-coded homepage.
- **Storefront (R02, R03, R14, R15):** Responsive 320px→desktop; six products in Mugs / Cups / Tumblers; supporting pages (story, contact, care, shipping & returns, privacy, terms); product search and customer accounts.
- **Commerce core (R04–R12):** Real finish/capacity variations (price, image, stock); persistent bag; guest checkout with optional accounts; Stripe cards + PayPal; AU-only shipping ($9.95 / free at discounted merchandise subtotal ≥ $100); per-variation stock, no backorders; coupons; transactional emails.
- **Explicit out of scope:** Direct bank transfer, subscriptions, wholesale, personalisation, gift cards, multilingual, international shipping.
- **Fictional exercise data:** Catalogue prices and promises are practice data; use labelled staging test dataset; owner supplies real SKUs, stock, photos, tax and policies before production.

### 3. Design and build constraints

- **Artboards:** 8 Pencil frames (Home/Product/Shop/Bag/Checkout desktop; Home/Product/Checkout mobile 390). Desktop 1440; breakpoint **1024px** for nav/layout switch.
- **Tokens:** Background `#F6F2EB`, primary `#243A31`, accents `#E9E0D3` / `#DDE2D7`; fonts **Newsreader** (brand/headings) + **Inter** (UI/body). Specs are drawn values; decisions override schematic quirks (16px+ mobile inputs, ~1.5 body line-height, ≥44px touch targets, separate State/Postcode).
- **No HF screens for:** supporting pages, account flows, search, empty/error/confirmation — implement from delivery.md + standard WooCommerce UX.
- **Exceptions that matter:** add Cups to category nav; 6 products/page (drop illustrative page-2); Stripe/PayPal UI supersedes drawn payment fields; reference photos are mood only.

### 4. Risks and dependencies

- Owner inputs (photos, inventory, tax, policies, Stripe/PayPal/hosting) block production launch; staging can proceed with test data.
- Payment correctness depends on webhooks + provider confirmation (not redirect alone); checkout must be uncached; retries must not double-charge.
- Free-shipping threshold uses **discounted merchandise subtotal ≥ $100** (decisions precedence over informal “over $100” copy).
- Pencil PNG/PDF export unavailable; use `.pen` + specs.md as source of truth.

### 5. Recommended architecture

- **Stack:** WordPress + WooCommerce; WooCommerce Stripe Gateway; official PayPal payments extension; native shipping zones/methods and coupons; transactional email via reliable SMTP/provider on hosting.
- **Theme:** Minimal WooCommerce-compatible theme or child theme implementing shared header/footer, product card, variation UI, bag and checkout chrome from the design system. Prefer block-editable homepage (hero, featured products, story) over hard-coded PHP.
- **Catalogue:** Variable products; attributes Finish + Capacity; variation-level price, image, stock; categories Mugs/Cups/Tumblers; clearly labelled staging/test dataset.
- **Custom code:** Prefer hooks/CSS and documented template overrides; no core hacks; minimise plugins.

## Recommended build steps

Follow acceptance.md suggested sequence, expanded for this pack:

1. **Scope lock** — Confirm R01–R15 and out-of-scope list with stakeholder; track decisions.md exceptions.
2. **Environment** — Staging WP + WooCommerce; backups; secrets outside VCS; Shop Manager + Admin roles.
3. **Theme foundation** — Tokens, typography, responsive shell (announcement, nav, menu panel, footer); fonts Inter + Newsreader.
4. **Templates** — Home (editable blocks), Shop, Product, Cart/Bag, Checkout, order result; supporting pages with shared chrome.
5. **Catalogue** — Categories, six variable products, variation matrix, test stock, featured products wiring.
6. **Cart & shipping** — Persistent cart; AU zone; $9.95 / free at ≥ $100 discounted subtotal; estimate vs confirmed quote.
7. **Checkout & accounts** — Guest checkout, optional accounts, search, field validation, AU address rules.
8. **Payments** — Stripe + PayPal sandbox; webhooks; success/pending/fail/cancel/retry paths; then production keys when owner accounts ready.
9. **Coupons, inventory, emails** — Percentage/fixed coupons; no backorders; customer + owner order emails verified.
10. **QA** — Run acceptance.md checklist (desktop/mobile, keyboard a11y, shipping edge cases, payment outcomes).
11. **Handover** — Owner walkthrough, operating guide, replace placeholders, controlled launch + live smoke test.

Suggested later work-item split (feature/fix briefs, not created here): theme shell → catalogue → cart/shipping → checkout/payments → content pages → QA/launch.
